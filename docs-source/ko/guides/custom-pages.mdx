사용자 정의 표시 페이지는 대시보드, 포털, 시각화 리포트, 계산기, 풍부한 인터랙션 페이지에 적합합니다. OpenYida는 최신 React 함수 컴포넌트를 Yida에서 실행 가능한 페이지로 컴파일하고 대상 페이지 컨테이너에 게시합니다.

## 엔드투엔드 흐름

```bash
openyida agent-capabilities --summary-json
openyida create-page <appType> "운영 대시보드"
# 페이지 소스 생성 또는 작성: project/pages/src/dashboard.canvas.jsx
openyida publish project/pages/src/dashboard.canvas.jsx <appType> <formUuid>
```

`agent-capabilities`로 환경, 로그인 상태, 사용 가능한 기능을 확인합니다. `create-page`는 페이지 `formUuid`를 반환하므로 추측하지 말고 명령 출력 또는 프로젝트 캐시에서 읽으세요. 소스가 준비되면 `publish`로 대상 페이지에 게시합니다.

## 페이지 규칙

새 페이지는 최신 페이지 흐름을 사용하며, 페이지 소스는 다음 규칙을 따라야 합니다:

- React 함수 컴포넌트를 페이지 진입점으로 사용합니다.
- `useState`, `useEffect`, `useMemo` 같은 Hooks를 사용할 수 있으며 side effect를 정리합니다.
- 지원되는 프런트엔드 리소스에서 UI 라이브러리, 차트, 아이콘을 `import`합니다.
- 버튼, 필터, 검색, Tabs, 페이지네이션, 카드는 실제 상호작용에 연결합니다.
- 실제 데이터는 Yida 데이터 브리지, 커넥터, Open API를 우선 사용하고 empty/error/refresh 상태를 제공합니다.
- 모바일에서도 읽기 쉽고 조작 영역이 넘치지 않게 합니다.

## 지원되는 Yida 네이티브 컴포넌트

사용자 정의 페이지는 Yida 네이티브 런타임 컴포넌트를 브리지할 수 있습니다. 먼저 `window.Deep`, `window.DeepYida`, `window.YidaNativeComponents`에서 탐지하고 실패하면 페이지 fallback을 렌더링해 빈 화면을 피합니다.

| 컴포넌트 / 시나리오 | 용도 | 연동 요구사항 |
| --- | --- | --- |
| `PortalTopBanner` / `PortalQuickEntry` | 포털 배너와 빠른 진입 | 포털 셸에 우선 사용하고, 없으면 자체 배너와 진입 카드로 fallback합니다. |
| `QuickAccessCard` / `RecentlyUsedCard` | 자주 쓰는 앱과 최근 사용 앱 카드 | `row-white` 또는 `column` 같은 `theme`을 반드시 전달하고 부분 fallback을 유지합니다. |
| `DataManageViews` | Yida 데이터 관리 뷰 임베드 | 대상 폼의 `form.appType`과 `form.value` / `formUuid`를 전달해야 합니다. |
| `EmployeeField` | 멤버 선택 | 실제 `onChange` 출력을 먼저 기록한 뒤 멤버 값으로 정규화합니다. |
| `DepartmentSelectField` | 부서 선택 | 검색, 팝업, 권한 안내, 단일/다중 선택을 먼저 검증합니다. |
| `AttachmentField` / `ImageField` | 첨부와 이미지 업로드 | 업로드 권한, OSS 서명, 미리보기, 삭제, 실패 상태를 먼저 검증합니다. |
| `DataCard` / `PortalContainer` | 포털 데이터 카드와 컨테이너 확장 | 대상 포털 컨텍스트, 데이터 설정, 스타일 변수가 검증된 뒤에만 사용합니다. |

네이티브 컴포넌트는 경험 향상 요소이며 페이지 안정성의 전제 조건이 아닙니다. fallback을 유지하고 제출 전에 멤버, 부서, 파일 값을 정규화하세요.

## 예시와 우수 사례

네이티브 컴포넌트는 smoke 예시로 컴포넌트와 권한을 먼저 확인합니다. 사용자 정의 페이지 우수 사례는 openyida-home 직达 경로 `/#/ko/showcase` 로 이동할 수 있습니다.

| 입구 | 링크 |
| --- | --- |
| 네이티브 컴포넌트 데모 | [canvas-native-components](https://demo.aliwork.com/o/openyida/sample/canvas-native-components) |
| 사용자 정의 페이지 우수 사례 | [쇼케이스](/#/ko/showcase) |
| Yida 컨테이너 직达 사례 페이지 | [openyidaRoute=showcase](https://demo.aliwork.com/o/openyida/helpCenter?openyidaLang=ko&openyidaRoute=showcase) |

## 복사 가능한 예시

```bash
openyida sample yida-canvas-custom-page native-components-smoke --output project/pages/src/native-components-smoke.canvas.jsx
openyida sample yida-canvas-custom-page portal-native-components --output project/pages/src/portal-native-components.canvas.jsx
openyida build-page project/pages/src/native-components-smoke.canvas.jsx --write
```

## 게시와 확인

```bash
openyida publish project/pages/src/dashboard.canvas.jsx <appType> <formUuid>
```

게시 전에 실제 상호작용, 모바일 대응, empty/error 상태, 필요한 데이터 연결이 포함되었는지 확인합니다. `publish`는 현재 소스를 `create-page`가 반환한 대상 페이지로 업데이트합니다.

## Yida 내비게이션 숨기기

전체 화면 대시보드나 데모 페이지에서는 플랫폼 내비게이션을 숨길 수 있습니다:

```bash
openyida update-form-config <appType> <formUuid> false "운영 대시보드"
```

내비게이션 다시 표시:

```bash
openyida update-form-config <appType> <formUuid> true "운영 대시보드"
```

## `build-page` 사용 시점

```bash
openyida build-page project/pages/src/dashboard.canvas.jsx --write
```

`build-page`는 로컬 페이지 소스만 처리하고 게시하지 않습니다. 리뷰, CI, 컴파일 출력 확인에 유용합니다.

