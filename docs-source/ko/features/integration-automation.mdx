## 사용 시나리오

통합 자동화는 폼 제출, 수정, 승인 완료 같은 업무 이벤트를 DingTalk 업무 알림, 폼 간 데이터 동기화, 후속 워크플로우, HTTP 커넥터 호출로 연결합니다.

## 프로세스 승인과의 경계

프로세스 승인은 승인 폼과 승인 노드 규칙을 담당합니다. 통합 자동화는 이벤트 이후의 알림, 데이터 동기화, 커넥터 호출, 외부 시스템 처리를 담당합니다.

## 설계 포인트

- 먼저 트리거 폼, 이벤트 유형, 실제 필드 ID를 확인하고 필드 라벨로 추측하지 않습니다.
- 게시 전에 AI Agent가 트리거 조건, 노드 목록, 수신자, 쓰기 대상을 포함한 흐름 요약을 보여주게 합니다.
- 운영 자동화는 먼저 초안으로 저장하거나 영향 범위를 확인한 뒤 게시합니다.
- 알림 제목, 내용, 값 매핑은 `#{fieldId-ComponentType}#` 형식의 필드 변수를 참조할 수 있습니다.

## 프롬프트 예시

```
고객 피드백 폼에 새 기록이 추가되면 담당자에게 DingTalk 업무 알림을 보내고 고객명, 문제 유형, 긴급도를 후속 폼에 동기화하는 통합 자동화를 만들어 주세요. 먼저 두 폼의 Schema를 읽고 흐름 요약을 보여준 뒤 확인 후 생성하고 게시하세요.
```

<Note>
통합 자동화는 실제 알림, 데이터 쓰기 또는 외부 API 호출을 발생시킬 수 있습니다. 실행 전에 대상 앱, 폼, 필드, 수신자를 확인하세요.
</Note>

## 기능 요약

| 시나리오 | 확인 항목 | 명령 / 기능 |
| --- | --- | --- |
| 폼 이벤트 트리거 | insert, update, delete, processFinish, activityTask | `openyida integration create` |
| DingTalk 업무 알림 | 수신자, 제목, 내용, 필드 변수 | `--receivers` / `--title` / `--content` |
| 폼 간 읽기 | 관련 폼에서 단일 기록 조회 | `--data-form-uuid` / `--data-condition` |
| 폼 간 쓰기 | 대상 폼 데이터 생성 또는 업데이트 | `--add-data-form-uuid` / `--add-data-assignment` / spec |
| 커넥터 액션 | HTTP 커넥터 또는 업무 API 호출 | `--connector-id` / `--action-id` / `--connection-id` |
| 게시 및 검사 | 초안, 게시, 진단, 결과 확인 | `--publish` / `openyida integration check` |

## 복사 가능한 명령

```bash
openyida integration create --help
openyida integration check --help
openyida agent-capabilities --summary-json
```

## AI Agent 프롬프트 템플릿

```
Yida 통합 자동화를 만들어 주세요. 먼저 트리거 폼과 대상 폼의 Schema를 읽고 이벤트, 트리거 조건, 노드 순서, 필드 매핑, 수신자, 게시 상태를 나열하세요. 제가 확인한 뒤 OpenYida로 흐름을 만들고 결과를 다시 읽어 주세요.

자동화 요구사항: [트리거와 후속 작업 설명]
```

## 검수 체크리스트

- 트리거 폼, 대상 폼, 필드 ID가 확인되었습니다.
- 흐름 노드, 수신자, 필드 매핑이 표시되고 확인되었습니다.
- 초안인지 게시 상태인지 명확합니다.
- 흐름 ID, 주요 리소스 ID, 검사 결과가 보고되었습니다.
