Halaman tampilan kustom cocok untuk dashboard, portal, laporan visual, kalkulator, dan halaman interaktif. OpenYida mengompilasi React function component modern menjadi halaman yang dapat berjalan di Yida dan memublikasikannya ke container halaman target.

## Alur end-to-end

```bash
openyida agent-capabilities --summary-json
openyida create-page <appType> "Dashboard operasional"
# Buat atau tulis sumber halaman: project/pages/src/dashboard.canvas.jsx
openyida publish project/pages/src/dashboard.canvas.jsx <appType> <formUuid>
```

Gunakan `agent-capabilities` untuk memeriksa lingkungan, status login, dan kemampuan yang tersedia. `create-page` mengembalikan `formUuid` halaman; jangan menebak, baca dari output perintah atau cache proyek. Setelah source siap, gunakan `publish` untuk memublikasikan ke halaman target.

## Aturan halaman

Halaman baru sebaiknya memakai alur halaman modern, dan source harus mengikuti aturan ini:

- Gunakan React function component sebagai entry halaman.
- Hooks seperti `useState`, `useEffect`, dan `useMemo` didukung; bersihkan side effect.
- `import` UI library, chart library, dan icon dari resource yang didukung.
- Button, filter, search, Tabs, pagination, dan card harus menjalankan interaksi nyata.
- Utamakan data nyata melalui Yida data bridge, connector, atau Open API; sediakan empty, error, dan refresh state.
- Layout mobile harus mudah dibaca dan area operasi tidak boleh meluap.

## Komponen native Yida yang didukung

Halaman kustom dapat menjembatani komponen runtime native Yida. Deteksi dulu dari `window.Deep`, `window.DeepYida`, atau `window.YidaNativeComponents`; jika gagal, render fallback milik halaman agar tidak blank.

| Komponen / skenario | Kegunaan | Syarat integrasi |
| --- | --- | --- |
| `PortalTopBanner` / `PortalQuickEntry` | Banner portal dan pintasan | Utamakan untuk portal shell; jika tidak ada, gunakan banner dan kartu pintasan fallback. |
| `QuickAccessCard` / `RecentlyUsedCard` | Kartu aplikasi sering dipakai dan terakhir dipakai | Wajib mengirim `theme`, seperti `row-white` atau `column`, serta mempertahankan fallback lokal. |
| `DataManageViews` | Menyematkan tampilan manajemen data Yida | Kirim `form.appType` dan `form.value` / `formUuid` dari form target. |
| `EmployeeField` | Pemilih anggota | Catat output `onChange` asli, lalu normalisasi nilai anggota. |
| `DepartmentSelectField` | Pemilih departemen | Verifikasi pencarian, popover, izin, pilihan tunggal, dan pilihan ganda. |
| `AttachmentField` / `ImageField` | Unggah lampiran dan gambar | Verifikasi izin unggah, tanda tangan OSS, pratinjau, hapus, dan status gagal. |
| `DataCard` / `PortalContainer` | Kartu data portal dan container | Gunakan hanya setelah konteks portal, konfigurasi data, dan variabel gaya terverifikasi. |

Komponen native adalah peningkatan pengalaman, bukan prasyarat stabilitas halaman. Pertahankan fallback dan normalisasi anggota, departemen, serta file sebelum submit.

## Contoh yang dapat disalin

```bash
openyida sample yida-canvas-custom-page native-components-smoke --output project/pages/src/native-components-smoke.canvas.jsx
openyida sample yida-canvas-custom-page portal-native-components --output project/pages/src/portal-native-components.canvas.jsx
openyida build-page project/pages/src/native-components-smoke.canvas.jsx --write
```

## Publikasikan dan konfirmasi

```bash
openyida publish project/pages/src/dashboard.canvas.jsx <appType> <formUuid>
```

Sebelum publikasi, pastikan source memiliki interaksi nyata, responsif mobile, empty/error state, dan logika data yang diperlukan. `publish` memperbarui source saat ini ke halaman target dari `create-page`.

## Sembunyikan navigasi Yida

Dashboard layar penuh atau halaman demo dapat menyembunyikan navigasi platform:

```bash
openyida update-form-config <appType> <formUuid> false "Dashboard operasional"
```

Tampilkan navigasi lagi:

```bash
openyida update-form-config <appType> <formUuid> true "Dashboard operasional"
```

## Kapan memakai `build-page`

```bash
openyida build-page project/pages/src/dashboard.canvas.jsx --write
```

`build-page` hanya memproses source lokal dan tidak memublikasikan. Cocok untuk review, CI, atau debugging output compile.
