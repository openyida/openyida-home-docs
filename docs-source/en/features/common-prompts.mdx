OpenYida is designed to be used directly by AI agents. Copy the prompts below into Qwen Office, Codex, Claude Code, Cursor, or another supported tool. The agent can check the environment, choose commands, run the workflow, and report the final result.

<Note>
For destructive actions, permission changes, app enable/disable operations, or public access changes, ask the agent to describe the target and scope before it proceeds.
</Note>

---

## Environment And Login

```
First check whether OpenYida is available: run openyida agent-capabilities --summary-json and confirm the current environment, login state, organization, and available commands. If I am not logged in, guide me through login.
```

```
Check which Yida environment and organization I am currently connected to, and tell me where new apps will be created.
```

```
Run OpenYida diagnostics and tell me whether Node.js, login state, project directory, and command capabilities are healthy.
```

---

## App Creation

```
Help me create a CRM Yida app. First understand the requirement and list the app structure, then create the app, forms, and required pages. When finished, tell me the app URL and created resources.
```

```
Generate a Yida app from the PRD below. First break down business objects, pages, form fields, workflows, and navigation. Then use OpenYida to create and publish the app, and return a usable link.

[paste PRD]
```

```
Build a project management app with projects, tasks, milestones, members, risks, and a progress dashboard. After creation, organize the app navigation so Home, Business Handling, Data Management, and Reports are easy to find.
```

## Forms And Workflows

```
Create a leave request form with employee name, department, leave type, start date, end date, and reason. Make employee name, leave type, and dates required.
```

```
Add a department field to the employee information form, with options Engineering, Marketing, Sales, and HR. Read the real form schema before updating fields.
```

```
Create a purchase approval workflow with applicant submission, manager approval, finance review, and archive. Tell me whether the workflow was published successfully.
```

<Note>
Field IDs cannot be guessed from field names. Before adding, updating, or writing form data, ask the agent to read the real schema.
</Note>

## Modern Custom Pages

```
Create a Yida custom page from this analysis document. First understand the business goal and information hierarchy, then build a modern React function-component page with clear visual hierarchy, real interaction states, and mobile responsiveness. When it is ready, use openyida publish to update the target custom page and tell me whether the page was published successfully.
```

```
Create an operations dashboard page with key metrics, trend charts, a task list, and anomaly alerts. It should support filters, refresh, empty states, error states, and mobile layout.
```

```
Improve the existing custom page into a B2B workbench: higher information density, clear navigation, and real interactions for buttons and filters. Publish it and verify the result.
```

## App Management

```
Organize this app's left navigation: put the entry page first and group Business Handling, Data Management, Reports, and System Settings clearly. List the current navigation before changing it.
```

```
Configure app localization: enable Chinese and English, then organize page titles, buttons, form fields, and message text. Tell me which texts were updated.
```

```
Query and adjust this app's administrator settings. Search for the user first, then add the selected member as a developer or data administrator. List current permissions before making changes.
```

```
Query this organization's Yida basic information, capacity, quota, and domain settings, then summarize what may affect app publishing.
```

```
Check whether this app is enabled. If it needs to be disabled or enabled, describe the impact and wait for my confirmation first.
```

## Data Management

Query the latest 20 records from [form name] and show key fields sorted by creation time descending.
```

```

```
Update the status field of the specified record. Confirm the instance ID and field ID before updating, then query the record back for verification.
```

## Sharing And Publishing

```
Publish [page name]. Before publishing, confirm the target appType, formUuid, and source path. After publishing, tell me whether the page is accessible.
```

```
Configure public access for [page name]. Before changing it, explain the public scope and risks, then wait for my confirmation.
```

```
Check whether this short link is valid and tell me which app or page it points to.
```

---

<Tip>
**Give the agent enough context.** Instead of "create a form", write: "Create a leave approval form with employee name, department, leave type (annual/sick/personal), start and end dates, and reason; make employee name, leave type, and dates required; then configure the approval workflow and return the page URL."
</Tip>
