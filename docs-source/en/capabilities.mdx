This list is for Yida users and AI agents. It is aligned with the current OpenYida command set and skill routing model. For exact parameters, run `openyida --help`, `openyida <command> --help`, or `openyida commands --json`.

<Note>
Use `openyida agent-capabilities --summary-json` as the default lightweight preflight. It returns version, login status, organization, workspace, and command-manifest digest without dumping the full runtime payload. Use `openyida agent-capabilities --json` only for full diagnostics, command contract checks, permission metadata, or raw login failure details.
</Note>

### Custom Page Chain Selection

| Need | Recommended chain |
|---|---|
| Modern React, Hooks, dashboards, workbenches, lists, detail pages, visualizations, or AI-first generation | Code Canvas: `.canvas.jsx` / `.canvas.tsx` / `YidaCodeCanvas` |
| Native Yida runtime components such as member, department, attachment upload, or image upload while keeping modern React | Code Canvas + native component bridge; run a smoke sample first, then add fallback and value normalization |
| The user explicitly asks for the classic custom page JSX/Jsx chain | Classic custom page: `.oyd.jsx` / `Jsx` |
| The page depends on `this.$(fieldId)`, `this.utils.yida.*`, `this.dataSourceMap`, form submit, or field two-way binding | Classic custom page: `.oyd.jsx` / `Jsx` |
| Migrate an existing `.oyd.jsx` page to Code Canvas | Use the `yida-canvas-upgrade` skill |

<Tip>
New custom pages default to Code Canvas. `check-page` and `compile` are mainly for classic custom page JSX. `.canvas.jsx` / `.canvas.tsx` pages are validated by the Canvas compilation stage inside `openyida publish`.
</Tip>

## Agent Capability, Evaluation, and Safety

| Capability | Command |
|---|---|
| Quickly determine workspace, login, organization, and command capability | `openyida agent-capabilities --summary-json` |
| Get full agent diagnostics | `openyida agent-capabilities --json` |
| Get full command manifest, side-effect, and permission metadata | `openyida commands --json` |
| Run no-side-effect routing evaluation | `openyida eval --mode routing [--skill <name>]` |
| Run documentation quality, safety, coverage, or comprehensive evaluation | `openyida eval --mode <doc-quality\|safety\|coverage\|comprehensive>` |
| Run real end-to-end evaluation | `OPENYIDA_E2E=1 openyida eval --mode <e2e\|generate>` |

`commands --json` exposes `sideEffect` and `permission` metadata for agent execution. For `mixed` commands, inspect the specific subcommand or arguments: for example, `data query` is read-only, while `data delete` is destructive; `nav-group list` is read-only, while `nav-group delete` requires confirmation.

<Warning>
Removed legacy login flags such as `--qr`, `--browser`, `--codex`, and `--qoder` are no longer supported. Use OAuth token login. Runtime-injected token mode only checks tokens injected by the host environment.
</Warning>
