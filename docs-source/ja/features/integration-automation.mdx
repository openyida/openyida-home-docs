## 利用シーン

連携自動化は、フォーム送信、更新、承認完了などの業務イベントを後続アクションにつなげます。DingTalk 作業通知、フォーム間データ同期、後続ワークフロー、HTTP コネクター呼び出しなどに使います。

## プロセス承認との境界

プロセス承認は承認フォームと承認ノード規則を扱います。連携自動化はイベント発火後の通知、データ同期、コネクター呼び出し、外部システム連携を扱います。

## 設計ポイント

- 先にトリガーフォーム、イベント種別、実際のフィールド ID を確認し、フィールド名から推測しない。
- 公開前に、AI Agent にトリガー条件、ノード一覧、通知先、書き込み先を含むフロー概要を出させる。
- 本番自動化では、先にドラフト保存するか影響範囲を明確に確認してから公開する。
- 通知タイトル、本文、データ代入では `#{fieldId-ComponentType}#` 形式のフィールド変数を参照できる。

## よく使うプロンプト

```
集成自動化を作成してください。顧客フィードバックフォームに新しいレコードが追加されたら、担当者へ DingTalk 作業通知を送り、顧客名、問題タイプ、緊急度をフォローアップフォームへ同期します。まず両方の Schema を読み、フロー概要を出し、確認後に作成して公開してください。
```

<Note>
連携自動化は実際の通知、データ書き込み、外部 API 呼び出しを発生させます。実行前に対象アプリ、フォーム、フィールド、受信者を確認してください。
</Note>

## 能力早見表

| シナリオ | 確認事項 | コマンド / 能力 |
| --- | --- | --- |
| フォームイベント発火 | insert、update、delete、processFinish、activityTask | `openyida integration create` |
| DingTalk 作業通知 | 受信者、タイトル、本文、フィールド変数 | `--receivers` / `--title` / `--content` |
| フォーム間読み取り | 関連フォームから 1 件を取得 | `--data-form-uuid` / `--data-condition` |
| フォーム間書き込み | 対象フォームへ作成または更新 | `--add-data-form-uuid` / `--add-data-assignment` / spec |
| コネクターアクション | HTTP コネクターまたは業務 API を呼び出す | `--connector-id` / `--action-id` / `--connection-id` |
| 公開と検査 | ドラフト、公開、診断、回読 | `--publish` / `openyida integration check` |

## コピー可能なコマンド

```bash
openyida integration create --help
openyida integration check --help
openyida agent-capabilities --summary-json
```

## AI Agent プロンプトテンプレート

```
Yida の連携自動化を作成してください。まずトリガーフォームと対象フォームの Schema を読み、イベント、トリガー条件、ノード順序、フィールドマッピング、通知先、公開状態を列挙してください。確認後、OpenYida でフローを作成し、結果を読み戻してください。

自動化要件：[トリガー条件と後続アクションを記述]
```

## 受け入れチェックリスト

- トリガーフォーム、対象フォーム、フィールド ID が確認済み。
- フローノード、通知先、フィールドマッピングが表示され確認済み。
- ドラフトか公開済みかが明確。
- フロー ID、主要リソース ID、検査結果が報告済み。
