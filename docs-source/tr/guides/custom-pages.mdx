Özel görüntüleme sayfaları panolar, portallar, görsel raporlar, hesaplayıcılar ve zengin etkileşimli sayfalar için uygundur. OpenYida modern React fonksiyon bileşenlerini Yida’da çalışabilir sayfalara derler ve hedef sayfa konteynerine yayınlar.

## Uçtan uca akış

```bash
openyida agent-capabilities --summary-json
openyida create-page <appType> "Operasyon panosu"
# Sayfa kaynağı oluştur veya yaz: project/pages/src/dashboard.canvas.jsx
openyida publish project/pages/src/dashboard.canvas.jsx <appType> <formUuid>
```

`agent-capabilities` ile ortamı, oturum durumunu ve kullanılabilir yetenekleri doğrulayın. `create-page` sayfa `formUuid` değerini döndürür; tahmin etmeyin, komut çıktısından veya proje önbelleğinden okuyun. Kaynak hazır olduğunda `publish` ile hedef sayfaya yayınlayın.

## Sayfa kuralları

Yeni sayfalar modern sayfa akışını kullanmalı ve kaynak kod şu kurallara uymalıdır:

- Sayfa girişi olarak React function component kullanın.
- `useState`, `useEffect`, `useMemo` gibi Hooks desteklenir; side effect temizliği yapın.
- Desteklenen kaynaklardan UI library, chart library ve icon `import` edin.
- Button, filter, search, Tabs, pagination ve card gerçek etkileşim çalıştırmalıdır.
- Yida data bridge, connector veya Open API üzerinden gerçek veriyi tercih edin; empty, error ve refresh state sağlayın.
- Mobile layout okunabilir olmalı ve işlem alanı taşmamalıdır.

## Desteklenen yerel Yida bileşenleri

Özel sayfalar Yida native runtime componentlerini bridge edebilir. Önce `window.Deep`, `window.DeepYida` veya `window.YidaNativeComponents` ile detect edin; başarısız olursa beyaz ekranı önlemek için sayfa fallback render edin.

| Component / senaryo | Kullanım | Entegrasyon gereği |
| --- | --- | --- |
| `PortalTopBanner` / `PortalQuickEntry` | Portal bannerı ve hızlı girişler | Portal kabuğunda öncelik verin; yoksa sayfa içi fallback kullanın. |
| `QuickAccessCard` / `RecentlyUsedCard` | Sık kullanılan ve son kullanılan uygulama kartları | `row-white` veya `column` gibi `theme` gönderin ve yerel fallback bırakın. |
| `DataManageViews` | Yida veri yönetimi görünümünü gömme | Hedef form için `form.appType` ve `form.value` / `formUuid` gönderin. |
| `EmployeeField` | Üye seçici | Önce gerçek `onChange` çıktısını kaydedin, sonra üye değerini normalize edin. |
| `DepartmentSelectField` | Departman seçici | Arama, popover, izin uyarısı, tekli ve çoklu seçimi doğrulayın. |
| `AttachmentField` / `ImageField` | Ek ve resim yükleme | Yükleme izni, OSS imzası, önizleme, silme ve hata durumlarını doğrulayın. |
| `DataCard` / `PortalContainer` | Portal veri kartı ve container geliştirmesi | Yalnızca portal bağlamı, veri ayarı ve stil değişkenleri doğrulandıktan sonra kullanın. |

Native componentler deneyimi geliştirir, sayfa kararlılığı için ön koşul değildir. Fallback kullanılabilir kalsın; üyeler, departmanlar ve dosyalar submit öncesi normalize edilsin.

## Kopyalanabilir örnekler

```bash
openyida sample yida-canvas-custom-page native-components-smoke --output project/pages/src/native-components-smoke.canvas.jsx
openyida sample yida-canvas-custom-page portal-native-components --output project/pages/src/portal-native-components.canvas.jsx
openyida build-page project/pages/src/native-components-smoke.canvas.jsx --write
```

## Yayınla ve doğrula

```bash
openyida publish project/pages/src/dashboard.canvas.jsx <appType> <formUuid>
```

Yayınlamadan önce kaynakta gerçek etkileşim, mobil uyum, empty/error state ve gerekli veri erişim mantığı olduğunu doğrulayın. `publish`, mevcut kaynağı `create-page` tarafından dönen hedef sayfaya günceller.

## Yida navigasyonunu gizle

Tam ekran pano veya demo sayfası platform navigasyonunu gizleyebilir:

```bash
openyida update-form-config <appType> <formUuid> false "Operasyon panosu"
```

Navigasyonu tekrar göster:

```bash
openyida update-form-config <appType> <formUuid> true "Operasyon panosu"
```

## `build-page` ne zaman kullanılır

```bash
openyida build-page project/pages/src/dashboard.canvas.jsx --write
```

`build-page` yalnızca yerel sayfa kaynağını işler ve yayınlamaz. Review, CI veya compile çıktısını debug etmek için uygundur.
