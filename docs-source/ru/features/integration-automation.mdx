## Когда использовать

Интеграционная автоматизация связывает бизнес-события, например отправку формы, обновление или завершение согласования, с последующими действиями: уведомлением DingTalk, синхронизацией данных между формами, следующим workflow или вызовом HTTP-коннектора.

## Граница с согласованием процессов

Согласование процессов отвечает за workflow-формы и правила узлов согласования. Интеграционная автоматизация отвечает за уведомления, синхронизацию данных, вызовы коннекторов и действия между системами после события.

## Проектные принципы

- Сначала подтвердите форму-триггер, тип события и реальные field ID; не угадывайте по названиям полей.
- Перед публикацией попросите AI Agent показать сводку flow: условия триггера, список узлов, получателей и цели записи.
- Для production-автоматизаций сначала сохраните черновик или подтвердите область влияния перед публикацией.
- Заголовки уведомлений, содержимое и assignments могут ссылаться на переменные полей в формате `#{fieldId-ComponentType}#`.

## Пример prompt

```
Создай интеграционную автоматизацию: когда в форме отзывов клиентов появляется новая запись, отправь DingTalk-уведомление ответственному и синхронизируй имя клиента, тип проблемы и срочность в форму сопровождения. Сначала прочитай Schema обеих форм, покажи сводку flow, затем создай и опубликуй после подтверждения.
```

<Note>
Интеграционная автоматизация может отправлять реальные уведомления, записывать реальные данные или вызывать внешние API. Перед выполнением подтвердите app, формы, поля и получателей.
</Note>

## Таблица возможностей

| Сценарий | Что подтвердить | Команда / возможность |
| --- | --- | --- |
| Триггер события формы | insert, update, delete, processFinish, activityTask | `openyida integration create` |
| Уведомление DingTalk | Получатели, заголовок, содержимое, переменные полей | `--receivers` / `--title` / `--content` |
| Чтение между формами | Запросить одну связанную запись | `--data-form-uuid` / `--data-condition` |
| Запись между формами | Создать или обновить данные целевой формы | `--add-data-form-uuid` / `--add-data-assignment` / spec |
| Действие коннектора | Вызвать HTTP-коннектор или бизнес API | `--connector-id` / `--action-id` / `--connection-id` |
| Публикация и проверка | Черновик, публикация, диагностика, чтение результата | `--publish` / `openyida integration check` |

## Команды для копирования

```bash
openyida integration create --help
openyida integration check --help
openyida agent-capabilities --summary-json
```

## Шаблон prompt для AI Agent

```
Создай интеграционную автоматизацию Yida. Сначала прочитай Schema формы-триггера и целевой формы, затем перечисли событие, условия триггера, порядок узлов, mapping полей, получателей и статус публикации. После моего подтверждения используй OpenYida для создания flow и чтения результата.

Требование к автоматизации: [опишите триггер и последующие действия]
```

## Чеклист приемки

- Форма-триггер, целевая форма и field ID подтверждены.
- Узлы flow, получатели и mapping полей показаны и подтверждены.
- Статус черновика или публикации понятен.
- Flow ID, ключевые resource ID и результаты проверки сообщены.
