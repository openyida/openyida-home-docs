Пользовательские страницы подходят для дашбордов, порталов, визуальных отчетов, калькуляторов и интерактивных страниц. OpenYida компилирует современные React functional components в страницы, которые запускаются в Yida, и публикует их в целевой контейнер.

## Сквозной процесс

```bash
openyida agent-capabilities --summary-json
openyida create-page <appType> "Операционный дашборд"
# Сгенерировать или написать исходный код страницы: project/pages/src/dashboard.canvas.jsx
openyida publish project/pages/src/dashboard.canvas.jsx <appType> <formUuid>
```

Используйте `agent-capabilities`, чтобы проверить окружение, статус входа и доступные возможности. `create-page` возвращает `formUuid` страницы; не угадывайте его, а читайте из вывода команды или кеша проекта. Когда исходный код готов, используйте `publish` для публикации в целевую страницу.

## Правила страницы

Новые страницы должны использовать современный процесс страницы, а исходный код должен соблюдать эти правила:

- Используйте React function component как вход страницы.
- Hooks вроде `useState`, `useEffect` и `useMemo` поддерживаются; очищайте side effects.
- Импортируйте UI library, chart library и icons из поддерживаемых ресурсов.
- Button, filter, search, Tabs, pagination и card должны запускать реальное взаимодействие.
- Предпочитайте реальные данные через Yida data bridge, connector или Open API; предусмотрите empty, error и refresh state.
- Mobile layout должен быть читаемым, а область действий не должна выходить за границы.

## Поддерживаемые нативные компоненты Yida

Пользовательские страницы могут подключать нативные runtime components Yida. Сначала выполните detection через `window.Deep`, `window.DeepYida` или `window.YidaNativeComponents`; если компонент не найден, рендерите fallback страницы, чтобы избежать белого экрана.

| Компонент / сценарий | Назначение | Требование интеграции |
| --- | --- | --- |
| `PortalTopBanner` / `PortalQuickEntry` | Баннер портала и быстрые входы | Используйте в portal shell; при отсутствии компонента показывайте собственный fallback. |
| `QuickAccessCard` / `RecentlyUsedCard` | Частые и недавно использованные приложения | Передавайте `theme`, например `row-white` или `column`, и сохраняйте локальный fallback. |
| `DataManageViews` | Встроенный вид управления данными Yida | Передавайте `form.appType` и `form.value` / `formUuid` целевой формы. |
| `EmployeeField` | Выбор сотрудника | Сначала зафиксируйте реальный `onChange`, затем нормализуйте значение. |
| `DepartmentSelectField` | Выбор отдела | Проверьте поиск, popover, права, одиночный и множественный выбор. |
| `AttachmentField` / `ImageField` | Загрузка файлов и изображений | Проверьте права загрузки, OSS signature, preview, удаление и ошибки. |
| `DataCard` / `PortalContainer` | Карточка данных и контейнер портала | Используйте только после проверки контекста портала, настроек данных и style variables. |

Нативные компоненты улучшают опыт, но не являются условием стабильности страницы. Сохраняйте fallback и нормализуйте сотрудников, отделы и файлы перед отправкой.

## Копируемые примеры

```bash
openyida sample yida-canvas-custom-page native-components-smoke --output project/pages/src/native-components-smoke.canvas.jsx
openyida sample yida-canvas-custom-page portal-native-components --output project/pages/src/portal-native-components.canvas.jsx
openyida build-page project/pages/src/native-components-smoke.canvas.jsx --write
```

## Публикация и проверка

```bash
openyida publish project/pages/src/dashboard.canvas.jsx <appType> <formUuid>
```

Перед публикацией убедитесь, что код содержит реальные взаимодействия, мобильную адаптацию, empty/error states и нужную логику данных. `publish` обновит текущий код в целевую страницу, возвращенную `create-page`.

## Скрыть навигацию Yida

Полноэкранный дашборд или demo page может скрывать навигацию платформы:

```bash
openyida update-form-config <appType> <formUuid> false "Операционный дашборд"
```

Показать навигацию снова:

```bash
openyida update-form-config <appType> <formUuid> true "Операционный дашборд"
```

## Когда использовать `build-page`

```bash
openyida build-page project/pages/src/dashboard.canvas.jsx --write
```

`build-page` обрабатывает только локальный исходный код и не публикует страницу. Это подходит для review, CI или отладки результата компиляции.

Когда будет готово, используй openyida publish для публикации в целевую пользовательскую страницу и сообщи, успешно ли опубликовано.
